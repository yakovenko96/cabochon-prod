# Функциональная проверка Cabochon — 2026-11-13

Проверены активные модули `cabochon_base` и `cabochon_manufacturing` на Odoo
19 Community. Итоговая версия изготовления — `19.0.2.40.0`.
Все действия с данными выполнялись в выделенных тестовых базах.
`Prod` не обновлялась, рабочий контейнер `odoo19-web` не перезапускался.

## Исправления

| Область | Наблюдаемое поведение после исправления |
| --- | --- |
| Совместные задачи | Сдача пресса/раскроя не требует тип формы от соседней задачи ЧПУ; сверление требует только свой размер. Видны операции строк, характеристики и фильтры справочников соответствуют каждой задаче. Чужую задачу подставить нельзя. |
| Черновик сдачи | Потери одного исходного мешка считаются по всем его строкам вместе. Изменение веса, признака окончательной сдачи и удаление строки пересчитывают итог. Нулевое закрытие не создает фиктивных потерь. |
| Мойка | Форма не требует характеристик сортировки. Литры учитываются только для толуола на каждой подтвержденной сдаче, в том числе частичной. |
| Обрезки | Возвратные потери раскроя поступают на склад полуфабрикатов и возвращаются через пресс без повторной мойки/сортировки. В совместной заявке движение относится именно к раскрою. Обычные потери остаются в зоне списаний. |
| Доступ менеджера | После выдачи мешка работнику менеджер читает исходный мешок в форме сдачи. Отдельное правило чтения не дает права изменять чужой склад или читать посторонние мешки. |
| Корректировка | При переносе с готового склада снимается неприменимый эталонный вес. Пустая причина и личная зона без сотрудника нужной компании запрещены. История сохраняется отдельным движением. |
| Таблица сдачи | Вложенная таблица использует перенос заголовков и длинных названий мешков/характеристик; в проверенном окне 1280 × 1400 все столбцы и обе строки видны полностью. |

Ранее созданные сводные мешки возвратных потерь автоматически не перемещаются.
Для переноса из `loss` администратор использует корректировку склада с причиной.
Старые подтвержденные движения и неизвестный расход толуола не переписываются.

## Покрытие

Каждая из 16 активных операций проведена от заявки и двойного подтверждения
выдачи до окончательной сдачи с годным выходом, выявленным/сделанным браком
и потерями. Проверены закрытие заявки и остатки:

- трубы; помывка в галтовке; помывка в толуоле;
- ручная сортировка; авто-сепаратор;
- подготовка камня; пресс; нормализация; раскрой;
- кабошонерка; шарокрутка; ЧПУ;
- шлифовка/полировка; лузговка; сверление; тонировка.

Архивная операция `sorting` не активировалась. Также проверены:

| Возможность | Проверка |
| --- | --- |
| Сквозное производство | Сырье → трубы → галтовка → ручная сортировка → пресс → шлифовка/полировка → готовый склад; происхождение и баланс веса. |
| Частичные операции | Остаток склада отделен от выданной части; несколько исходных мешков для труб, частичные/окончательные/нулевые сдачи. |
| Ошибочные действия | Повторное проведение, чужие источники и задачи, неподходящий маршрут, недостаток остатков, отмененная заявка, запрещенные роли/компании. |
| Брак и обрезки | Накопление, возврат брака в обработку, повторное использование обрезков через пресс. |
| Готовые изделия | Объединение позиций, эталонный вес и расчетное количество, многопозиционная продажа; откат всей выдачи при превышении остатка и защита от повторов. |
| Контрагенты | Только необработанное сырье на выдачу, частичный остаток, прием разных стадий, неизменяемые движения и отчет выданного/полученного. |
| Уведомления | Очередь менеджер → работник, отказ, права адресата; повторный вызов обработки просрочки не дублирует активность, отмена снимает уведомления. |
| Справочники и роли | Создание/правка/архивация, допуски операций сотрудников, смена роли без сохранения прежних повышенных прав. |
| Отчеты и меню | Формирование представлений, чтение записей и агрегаты SQL-отчетов: администратор — 31 действие, технолог — 21, менеджер — 20, менеджер готового склада — 17, работник — 7. |
| Браузер | Через Playwright MCP открыты все 31 действие: списки, справочники, отчеты и мастера. Диалогов ошибок не обнаружено. |
| Этикетки и поиск | HTML и PDF этикетки; HTTP 200, `%PDF-1.4`, одна страница. Поиск по коду учитывает доступ к мешку. |

Итоговые результаты:

- Обновление существующей `CabochonAudit20261113Test`: тот же результат, 55 тестов.
- `SMOKE_ZERO_START_OK`; `CONCURRENCY_OK`: объединение готовых позиций, резерв, однократная выдача, отмена против приемки, выдача контрагенту.
- Ruff 0.17.5: `All checks passed!`; `compileall`, `scripts/validate_xml.py` (13 файлов), `git diff --check`: успешно.
- Playwright MCP: совместная сдача раскрой + ЧПУ подтверждена кнопками менеджера и работника (тестовый администратор с явной отметкой замещения). Вход 100 г, выход 80 г, обрезки 10 г, обычные потери 10 г; заявка закрыта, ошибок консоли нет.
- После последней правки отображения выполнено успешное обновление тестовой базы; геометрия таблицы: ширина содержимого равна ширине контейнера (1183 px), скрытого горизонтального остатка нет. [Скриншот полной таблицы](../.playwright-mcp/cutting-cnc-receipt-complete.png).

Основная регрессия: `addons/cabochon_manufacturing/tests/`, включая
`test_operation_workflows.py`. Полный безопасный запуск на новой базе:
`scripts/run_odoo_tests.py`; параметры приведены в `TESTING.md`.

Физический принтер и аппаратный сканер не подключались. Расписание cron
в тестовом веб-сервере отключено; обработчик просрочек проверен прямым вызовом.
Удаленный GitHub Actions не запускался. Проверки не заменяют проверку
миграции на свежей резервной копии рабочей базы и приемку на реальных данных.

При чистой установке загрузчик описаний модулей напечатал сообщение docutils
о неправильном отступе. Оно не остановило установку; к бизнес-ошибкам
приложения этот вывод не отнесен, источник описания не локализован.
